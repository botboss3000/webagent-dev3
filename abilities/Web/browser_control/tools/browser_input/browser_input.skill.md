# browser_input

## Usage

- Click, type or press a key in the private server browser, scroll it with the wheel, pinch or hover, or save the site's sign-in.
- Each click, type, press, touch, wheel, pinch or hover needs a browser_read read under 120 seconds old whose region contains the target.
- Sign-in fields take a vault entry (vault), never literal passwords; save_login keeps the signed-in site for later visits

Input on the page: click, type literal text or a vault entry, press one allow-listed key, touch, wheel, pinch, hover, or save the site's sign-in. Read the region first with browser_read; the result reports the target used and, for press, touch and pinch, the element focused afterwards. A failed input did nothing; an uncertain one may have: read before repeating it.

- `click` `selector`, `type` `selector` `text` or `vault`, `press` `key` (`selector`): each needs a read under 120 seconds old, on the same URL, whose region (its selector, or the whole body) contains the target. Each input uses up that read. Changes elsewhere on the page, such as live timestamps, do not matter. The result reports the `target` it used (tag and visible label). Password and credential fields take only a `vault` entry, never literal text. `press` takes one of Tab, Shift+Tab, Enter, Escape, Space, ArrowUp, ArrowDown, ArrowLeft, ArrowRight, Home, End, PageUp, PageDown, sent to `selector` or to the focused element, and reports the element `focused` afterwards.

- `touch` `selector` (`dx`, `dy`): a real finger touch on the element's centre, sent as trusted touch events, so native scrolling and focus changes happen as on a phone. Without `dx`/`dy` it is a tap; with them it drags that many pixels (at most 2000). Needs a touch viewport (`viewport` `phone` or `tablet` first). The result reports `focused` (the element holding focus afterwards) and the target's `scroll_before`/`scroll_after` (`left`, `top`). It also reports `gesture`: `owner` is `browser` when the browser took the pan for native scrolling (it fired `pointercancel` or made `touchmove` uncancelable) and `page` when the page kept it, with the counts. On a phone, a native scroll starting while the keyboard is open can dismiss the keyboard, so `owner` is the evidence for that class of bug; the effective `touch-action` comes from the touched element up to its nearest scroll container, not from rows above it. Use it to reproduce and verify focus, keyboard and gesture bugs: focus the text box, read, touch-drag the row, and check that `focused` is still the text box. There is no on-screen keyboard in this browser; on a phone the keyboard closes when the text box loses focus, so `focused` is the check.

- `wheel` `selector` (`dx`, `dy`): a real mouse wheel at the element's centre, sent as a trusted wheel event, so the page's own `wheel` handlers run instead of a scroller being moved by script. Use it for pointer-anchored zoom, wheel-hijacked strips and anything that listens for `wheel`: `browser_read` `scroll` moves the scroller directly and never fires a wheel event. A distance is required; negative `dy` scrolls up and negative `dx` scrolls left. It needs no touch viewport. The result reports `delta`, the target's `scroll_before`/`scroll_after` and `focused` is not touched, so read the page afterwards to see the effect (for example the zoom level a viewer applied).

- `pinch` `selector` (`dx`, `dy`): a real two-finger pinch centred on the element, sent as trusted touch events, so an in-app pinch-to-zoom handler zooms about that point rather than the page zooming. The fingers start 40 px apart and each travels `dx`/`dy`, so a positive `dx` spreads them (zoom in) and a negative one brings them together; the result reports `spread_before`/`spread_after`. Needs a touch viewport (`viewport` `phone` or `tablet` first), like `touch`.

- `hover` `selector`: a trusted mouse move to the element's centre, so `:hover` styles, tooltips and pointer handlers react as with a mouse. It clicks and focuses nothing. The result reports the `hovered` element under the pointer afterwards (tag, id, visible label); `browser_read` `measure` `styles` then shows the computed style that changed.

- `type` `selector` `vault` (`totp`): types the user's vault entry into a sign-in field (user name, email, password or one-time code) on the entry's own https site. You never see the value, and it is removed from every result. With `totp: true` the entry is an authenticator secret and its current code is typed.
- `save_login` `origin`: once the page shows the user signed in, saves the site's sign-in (its cookies and the steps since the last navigate) to the user's private store, after the user approves. Later navigations to that site open signed in, and sign in again with the steps when the site asks.

For a known sequence, use one `script` call instead of one call per action: for example navigate, read the target region, click, wait_for, then a final step with `"screenshot": true`. Mark only the steps whose image you need.
