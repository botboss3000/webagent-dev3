# browser_input

Input on the page: click, type literal text or a vault entry, press one allow-listed key, touch, or save the site's sign-in. Read the region first with browser_read; the result reports the target used and, for press and touch, the element focused afterwards. A failed input did nothing; an uncertain one may have: read before repeating it.

- `touch` `selector` (`dx`, `dy`): a real finger touch on the element's centre, sent as trusted touch events, so native scrolling and focus changes happen as on a phone. Without `dx`/`dy` it is a tap; with them it drags that many pixels (at most 2000). Needs a touch viewport (`viewport` `phone` or `tablet` first). The result reports `focused` (the element holding focus afterwards) and the target's `scroll_before`/`scroll_after` (`left`, `top`). It also reports `gesture`: `owner` is `browser` when the browser took the pan for native scrolling (it fired `pointercancel` or made `touchmove` uncancelable) and `page` when the page kept it, with the counts. On a phone, a native scroll starting while the keyboard is open can dismiss the keyboard, so `owner` is the evidence for that class of bug; the effective `touch-action` comes from the touched element up to its nearest scroll container, not from rows above it. Use it to reproduce and verify focus, keyboard and gesture bugs: focus the text box, read, touch-drag the row, and check that `focused` is still the text box. There is no on-screen keyboard in this browser; on a phone the keyboard closes when the text box loses focus, so `focused` is the check.

- `type` `selector` `vault` (`totp`): types the user's vault entry into a sign-in field (user name, email, password or one-time code) on the entry's own https site. You never see the value, and it is removed from every result. With `totp: true` the entry is an authenticator secret and its current code is typed.
- `save_login` `origin`: once the page shows the user signed in, saves the site's sign-in (its cookies and the steps since the last navigate) to the user's private store, after the user approves. Later navigations to that site open signed in, and sign in again with the steps when the site asks.

For a known sequence, use one `script` call instead of one call per action: for example navigate, read the target region, click, wait_for, then a final step with `"screenshot": true`. Mark only the steps whose image you need.
