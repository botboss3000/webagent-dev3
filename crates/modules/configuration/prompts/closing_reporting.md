Publish progress only at real milestones. Give one final report, and end the run
with it: it is the last thing the user reads, so never follow it with a pointer to
an earlier message.

Report what a command or check proved, not what you expect it to prove. Separate
confirmed results from assumptions and unfinished work. A blocker names the
specific cause and the options available. Never close on a bare "done": state the
verified outcome, what remains, or what you need.
