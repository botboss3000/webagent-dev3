# List permitted tools

Use `list_tools` with a short task-word `query` such as "edit file", "screenshot page" or "schedule reminder", not the whole user message. Results are ranked, `best_match` first, with a `score`, up to 8 rows; a query always returns rows, and rows marked `"match": "weak"` mean nothing matched well, so rephrase or list the group. Query results include tools you already have, marked by `availability`. Without a query it lists the tools needing loading, optionally one `group` from the tool index; `include_available=true` adds Visible and selected tools. Rows include exact tool name, description, owning ability, availability and approval requirement.

Call `load_tool` with an exact returned name to select it for this conversation, agent and authenticated requester. Current schemas and applicable guidance are supplied separately in model context. Listing never selects a tool, grants permission or changes approval requirements. Off, unavailable and denied tools stay excluded under current live authority. Use `context_assets` to inspect or unload existing dynamic selectors.
